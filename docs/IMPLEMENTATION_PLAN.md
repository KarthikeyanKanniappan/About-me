# Portfolio — Implementation Plan

Source: `~/Downloads/portfolio-plan.md`. This file turns that plan into ordered steps we can review, then implement one milestone at a time. Each milestone ends with a check, and a commit.

**Environment (checked 2026-10-12):** Node 20.11.1 · npm 10.2.4 · create-next-app 16.4.0 · Tailwind 4.3.3
**Repo:** `Portfolio/` is its own git repo, `origin → KarthikeyanKanniappan/About-me`, `main`. (The GitHub repo turned out to be empty, so step 1.2's merge was not needed.)

## Status (2026-10-12)

Milestones 1–5 and the SEO part of 6 are built with dummy content and all decisions at their defaults. Still to do: real content (D5), Resend key (D6), Lighthouse pass, Vercel deploy.

Differences from what's written below:

- Scaffolded in a temp folder and copied in, because npm rejects the capitalised folder name `Portfolio`.
- create-next-app 16.4 enables `cacheComponents` + `partialPrefetching`; all pages still prerender as static. The footer year uses `"use cache"` as Cache Components requires.
- zod 4: `z.email()` and `z.flattenError()`. The action reads named fields only, so the honeypot is checked before validation and isn't in the schema.
- lucide-react 1.x has no brand icons; LinkedIn/GitHub/X are inline SVGs in `components/SocialIcon.tsx`.
- Placeholder images are SVGs rendered with `unoptimized`; switch to JPG/PNG for real photos.
- The OG image is generated by `app/opengraph-image.tsx` instead of a static `og.png`.
- Circle buttons are `size-24` below `sm` so all three fit in one row at 375px.
- Extra env vars: `CONTACT_FROM_EMAIL`, `NEXT_PUBLIC_SITE_URL`.

create-next-app sees the existing `.git` and skips its own `git init`.

Gives utilities like `bg-bg`, `text-muted`, `border-line`, `bg-accent-orange`, `font-heading`.

## Milestone 5 — Contact (`/contact`)

**5.1 Server Action** — `app/contact/actions.ts` (`"use server"`):

```ts
const schema = z.object({
  firstName: z.string().trim().min(1, "Required"),
  lastName: z.string().trim().min(1, "Required"),
  email: z.string().trim().email("Enter a valid email"),
  subject: z.string().trim().max(150).optional(),
  message: z.string().trim().min(10, "At least 10 characters").max(5000),
  company: z.string().max(0).optional(), // honeypot
});

export type ContactState = {
  ok: boolean;
  message?: string;
  fieldErrors?: Partial<Record<string, string[]>>;
};
```

- Read fields with `Object.fromEntries(formData)` (missing honeypot → `undefined`, which `.optional()` accepts — fixes the bug in the source plan).
- Honeypot filled → return `{ ok: true }` silently (don't tip off bots).
- Validation failure → `{ ok: false, fieldErrors }`.
- Missing env vars → `{ ok: false, message: "Email isn't configured yet." }`.
- Send via Resend: `from: "Portfolio <onboarding@resend.dev>"` until a domain is verified, `to: CONTACT_TO_EMAIL`, `replyTo: email`, plain-text body.
- Resend error → generic error message; log details server-side only.

**5.2 Form** — `components/ContactForm.tsx` (`"use client"`):
- `useActionState(sendMessage, initialState)`.
- Labelled inputs, required ones marked `*` and `required`; square corners, `border border-ink`, `focus-visible:ring-2`.
- Field errors under each input, linked with `aria-describedby`; status message in an `aria-live="polite"` region.
- Hidden honeypot: `company` input, visually hidden, `tabIndex={-1}`, `autoComplete="off"`.
- Submit: full-width orange pill, `disabled={pending}`, label "Sending…" while pending.
- On success, reset the form (`formRef.current?.reset()` in an effect keyed on state).

**5.3 Page** — `app/contact/page.tsx`: left column title, "Looking forward to hearing from you", email (+ phone if set); right column form. Page `metadata`.

**5.4 Env** — `.env.local` (gitignored by default) + committed `.env.example`:

```
RESEND_API_KEY=
CONTACT_TO_EMAIL=
```

**Check:** submit empty → field errors; valid submit → email arrives with correct reply-to; filled honeypot → fake success, no email. **Commit.**
